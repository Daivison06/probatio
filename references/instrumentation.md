# Instrument real execution

Produce `models/instrumentation.md` before editing an isolated source copy. For each model action, specify the source revision/symbol, operation boundary, actor identity, captured fields, pre/post timing, and synchronization that makes the observation meaningful. Record unobservable fields and their effect on coverage.

Run actual implementation methods. A simulator or mock of the critical storage/concurrency mechanism cannot establish correspondence with that mechanism. Reuse project tests where useful, with real local dependencies for the behavior under investigation. Never bootstrap a production environment merely to generate traces.

## Capture contract

The bundled trace compiler accepts one JSON object per line with exactly these fields:

```json
{"actor":"worker-A","seq":1,"start_ns":100,"end_ns":110,"action":"acquire","data":{"key":"example"},"state":{"owner":"worker-A"}}
```

Numbers above illustrate the schema, not real evidence. Capture times with a shared monotonic clock; per-actor sequences start at one and are contiguous. `data` describes action inputs; `state` is the explicitly modeled observation. Map large identifiers/timestamps to small symbolic values rather than overflowing TLC integers. Metadata and timestamps are not part of `state` unless the model deliberately represents them.

Capture within the operation's actual synchronization/linearization boundary when possible. A post-operation read racing with other writes is not necessarily that operation's post-state. Document its observation semantics and model a separate observation action when necessary. Include asynchronous steps separately instead of falsely declaring a multi-step operation atomic.

For low-level concurrency, prefer per-thread buffers and operation intervals; adding a global lock can suppress the bug. A single file can contain interval events from several actors. The compiler uses per-actor order and non-overlapping intervals, never file order between actors. Its built-in strategy requires a shared clock domain. Distributed clocks require a custom causal mapping; do not compare unsynchronized timestamps as a total order.

The bundled wrapper checks complete observation records by equality. Encode deliberate partial observations in the model's `Observe` record and document omitted fields. Do not silently drop fields to make a trace pass. Instrumentation itself can perturb scheduling even in distributed code; record this limitation.

For every observation field, distinguish a raw implementation value, a deterministic abstraction of a raw value, and a harness-maintained witness. Preserve raw values and the projection rule alongside the trace. A synthetic owner label, expected outcome, or symbolic deadline is not independent evidence that the implementation stores that owner, returned that outcome, or has that deadline. Assert actual return values and payloads before projecting them; document when distinct TTLs or payloads are intentionally collapsed. A matching trace validates only this projection.

## Outputs and gate

- An isolated instrumentation patch or wrapper, plus its source baseline.
- `harness/` with a reproducible command, local dependency lifecycle, and cleanup.
- Nonempty `traces/*.ndjson` generated by executed scenarios, with logs and exit status.
- Event/action/state-field coverage and any missing scenarios.

Preserve raw traces. A corrected capture requires a new run, not rewriting evidence. Mutated traces are useful only as explicitly labeled negative controls. Complete this phase when capture provenance, semantics, and coverage are established; JSON validity alone is insufficient.
